# RSGNL Studio Website

The RSGNL Studio website. A 3D nature landscape sits behind the page as a single fixed WebGL canvas, while normal HTML sections scroll on top of it. A Day/Night switch at the top centre turns between two worlds that share one layout: by day a painted, brushstroke meadow; by night the same meadow as fine glowing dust, lit by a light that follows the cursor. During the switch the sun sets, the camera flies up to a top view, and the whole painting takes on the night light and sinks into the dark while the dust condenses under that same light (and back on the way home). The whole scene is driven by one `night` value (0 = day, 1 = night). All text stays in the DOM for SEO and accessibility.

## Stack

| Library | Why |
| --- | --- |
| Next.js 16 (App Router, Turbopack) | Routing, server rendering of the DOM content, and a root layout that keeps the canvas mounted across routes |
| React 19 + TypeScript | UI and type safety |
| Tailwind CSS 4 | Utility styling, with design tokens in a CSS-first `@theme` |
| three | WebGL rendering |
| @react-three/fiber | Declarative React renderer for three |
| @react-three/drei | Ready-made R3F helpers (sky, stars, loaders, etc.) |
| @react-three/postprocessing / postprocessing | Post-processing stack (EffectComposer) |
| gsap + ScrollTrigger | Section scroll triggers and future tweens |
| lenis | Smooth scrolling, driven by GSAP's ticker |
| zustand | Small store that bridges DOM and canvas without re-renders |
| lucide-react | Icons (the sound toggle, the contact CTA) |

## Getting started

Prerequisites: Node 22 (see `.nvmrc`) and npm.

```bash
nvm use            # Node 22
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run start      # serve the production build
npm run lint       # ESLint
npm run typecheck  # generate route types, then tsc --noEmit
```

## Architecture

- **The canvas lives in the root layout and the DOM sits on top.** `src/app/layout.tsx` renders `SceneCanvasLoader`, a small client wrapper that loads `SceneCanvas` with `next/dynamic` and `ssr: false`. The canvas is `position: fixed`, full-viewport, behind `<main>`, and has `pointer-events: none`. Because it lives in the layout, it stays mounted when routes change.
- **The zustand store is the only bridge.** `src/store/scene.ts` holds `activeSection`, `sectionProgress`, `scrollProgress`, `timeOfDay`, `night`, `sceneReady`, `entered`, `intro`, `sceneMode`, `hoveredBed` and `openBed`, and for the night map `nightIntro`, `panel`, `activePath`, `pathStation`, `hoveredPlace` and `placeScreen` (a buffer of screen positions the canvas fills in place every frame). The DOM writes to it and the canvas reads from it. Per-frame code reads it with `useSceneStore.getState()` inside `useFrame` and never subscribes, so scrolling causes no React re-renders.
- **The section config is the single source of truth.** `src/config/sections.ts` gives each section an `id` and a camera keyframe (`position`, `lookAt`, optional `up`, `fov`). The page renders its `<section>`s from this config, the scroll hook registers one trigger per entry, and the scene reads the same entries through `sectionsByMode` in `src/config/scene.ts`.
- **Scroll drives the store.** A page calls `useSectionScroll(sections)`. This hook creates Lenis (synced with GSAP's ticker and ScrollTrigger), registers one ScrollTrigger per section plus one for the whole page, and writes `activeSection`, `sectionProgress`, and `scrollProgress`. When the page unmounts, or Next hides it with `<Activity>`, the hook kills every trigger and destroys Lenis.
- **The entry screen.** `EntryScreen` (DOM, over the canvas) is the first thing on screen. The world waits behind it at the opening frame of the build-up (`INTRO_BUILD_FROM`: sky, mountains and far trees painted, the meadow still dark; the canvas fades in once `CameraRig` reports its first frame as `sceneReady`). A short note says the site is best with sound, and two stacked buttons offer "Enter with sound" and "Enter without sound". Their click is the user gesture browsers need before audio, so the sound can swell in with the intro; it sets `entered`, which starts the intro, and the screen fades away. If the intro hasn't started moving a few seconds later (the scene isn't running, e.g. no WebGL), it is finished at once, so the UI and the sound don't wait for it.
- **The intro builds the world.** Once the visitor has entered, `CameraRig` advances the store's `intro` (0 to 1) over `INTRO_DURATION` (6.5 s), and zooms the camera in all through the build-up (moving in from `INTRO_CAMERA_OFFSET`, back and up, and narrowing from a wider FOV, `INTRO_FOV_OFFSET`), easing out as the world is finished. `Lights` hands it to the shaders as `uBuild` (`painterly/build.ts`, from `INTRO_BUILD_FROM` up to 1): like a painter working back to front, the sky is painted first from the horizon up, then the land from far to near in broad sweeps along the horizon, out of the night's void (`morphPaint` does this for every painted material), while each plant grows up from its root as its spot is painted. Mist and pollen settle in last. Once `intro` passes `INTRO_UI_AT`, the UI appears (`useIntroRevealed`, `useReveal`: a GSAP fade and rise with a long ease-out, staggered) and the featured flowers react.
- **The cursor is a dot.** `CursorDot` (in the root layout, so on every page) replaces the system cursor with a small dot that inverts what's beneath it (`mix-blend-difference`). It grows over links, buttons and a hovered flower bed, shrinks a little while pressed, and hides for touch (a pen gets it too). The system cursor is hidden by the `cursor-dot` class in `globals.css`, only while the dot is mounted and only for fine pointers. The dot is a popover in the top layer, raised again whenever a modal dialog opens, so it stays above the project overlay. In view transitions it is its own live layer (`view-transition-name: cursor-dot`), so the page slide doesn't carry it off with the root snapshot.
- **Everything eases softly.** The CSS tokens `ease-smooth` (state changes), `ease-reveal` (arrivals) and `ease-overlay` (the overlay slide, 1.2 s) in `globals.css` are used for every transition.
- **The Day/Night switch drives `night` and the camera.** `DayNightSwitch` (in the top navigation pill, top centre) only writes `timeOfDay` to the store. `CameraRig` moves `night` toward it over `DAY_NIGHT_DURATION` (5.5 s, cubic ease in and out, smoothed by a critically damped spring so that clicking mid-way turns it around without a jerk) and blends the camera with the same value, position and rotation together: from the mode's first keyframe in the meadow (day) to `nightCamera` in `src/config/scene.ts`, high above the meadow and looking straight down (night). It also fits the FOV to the aspect ratio and adds idle drift and mouse parallax (off with reduced motion). Still to come: interpolating the camera between section keyframes using `sectionProgress`.
- **Two worlds, one morph.** `PaintedWorld` (terrain, mountains, vegetation) is the day; `DustWorld` (`Dust`, `Fireflies`, `CursorLight`) is the night. `updateLight` turns `night` into `uMorph` (`MORPH_RANGE` in `src/config/scene.ts` sets when it runs), and the change happens everywhere at once, with no mask or front. Both worlds share one night light model (`painterly/nightLight.ts`: a moonlit base that breathes in slow drifts, plus the cursor light). Every painted material ends with `morphPaint`: over the first half of the morph the paint is re-lit by that night light (so the cursor light already moves over the painting), over the second half it sinks into the void (`voidColor`, the same dark the sky turns into). The dust fades in over the middle, lit the same way, so the specks condense out of the paint's own light. The dust is drawn slightly nearer the camera in depth (same spot on screen), so the paint it sits on doesn't hide it. Each world stops rendering once it is fully gone.
- **The nightingale is the night's light.** `Nightingale` (between the two worlds in `Scene`) flies circles around the cursor by day, at the depth of field's focus distance (`focusDistance` in `painterly/view.ts`) so it stays sharp, beating its wings in bursts and banking into its turns (it wanders on its own on touch screens or when the mouse leaves). It is painted from a dozen strokes of the brush atlas (`painterly/nightingale.ts`: brown back, buff breast, rufous tail, two wings that beat around the shoulder), and every fragment writes the depth of its centre, so depth of field blurs it as one thing. It writes the night light's position (`dustUniforms.uLightPos`) every frame: by night that is the place above the ground under the cursor, and as the day turns into the night it kindles into the light's color (HDR, so it blooms), dives along the cursor's ray down to that place and fades into the light's core (`NIGHTINGALE` in `src/config/scene.ts` sets its size, circles, wingbeat and these ranges). So the light that re-lights the painting during the morph comes from the bird.
- **The dust world.** `Dust` draws its specks with one material: the ground with a rippled micro relief, the conifers from the shared `scatterConifers` layout (squatter, so they read as crowns from above), flower clusters in drifts of color, the flower beds in their own colors (from the shared `scatterBeds` layout), the stream left dark as a ribbon through it, and a few motes floating near the camera. The ground and its flowers cover more than any one screen shows: the night camera fits the whole map to the screen, so wide and square screens see more ground around it. `NIGHT_GROUND` (`painterly/landscape.ts`) sets how far it reaches: full density as far as screens from portrait phones to ultrawides see, then thinning and fading out softly past what a 32:9 screen sees, so no screen meets a hard edge. That ground is split into 80 m tiles, each its own culled `points` draw call, so a screen only draws what it shows, and they are built in idle time after load, nearest the map first. The trees, the city, the beds and the motes are one draw call, built up front. Unlit, it is a faint moonlit haze. `CursorLight` is drawn where the nightingale has put the light, above the ground under the cursor, lights the dust around it in HDR so it blooms, and sets the focus: specks away from it open into dim bokeh discs. Its wake is recorded in a small ping-pong texture (`DustTrail` in `painterly/dust.ts`) that decays and spreads; dust in the wake is swept along, swirls and glows, then settles.
- **The top view.** As the camera rises (`viewUniforms.uTopView`), the plants tip over from facing the camera upright to facing it from above, the mist thins out, and the ground swaps its sideways day strokes for even ones early in the flight (they are laid out for the low camera and would stretch into big smears from higher up), while it all turns into dust. Part of the grass and flowers are scattered over the area seen from above (`OVERHEAD` in `painterly/landscape.ts`), and the terrain reaches past the day camera so its edge never shows.
- **The scene is painted, not lit.** Every material is an unlit `ShaderMaterial`. Colors come from `src/config/palette.ts` in three sets: warm day, sunset (dusk) and cold night. `src/components/canvas/painterly/palette.ts` turns them into shared uniforms (`uSkyTop`, `uFlowerPink`, …). `Lights` calls `updateLight(night)` once per frame. That mixes day to dusk over `night` 0–0.5 and dusk to night over 0.5–1, sinks the sun behind the mountains, raises the moon, and turns up the night glow (glowing flowers, fireflies, stars, bloom).
- **The day is built from brushstrokes.** There is no brush filter over the frame: every surface is made of strokes. `painterly/brushes.ts` simulates single strokes bristle by bristle at startup (flat, filbert, round and dab brushes, eight variants each): streaks, paint running dry, impasto ridges, and opacity from the thickness of the paint film, so tails, edges and dry-brush streaks are translucent. Plants are sets of strokes (`painterly/plants.ts` paints a flower as stem, leaves, petals and a centre, a fir as a dark mass, branch jabs and a few lit tips), collected in a `StrokeBuffer` and drawn as instanced ribbons (`painterly/strokes.ts`), one layer per kind. Each stroke follows a smooth cubic Bézier curve (its bend arcs it, its wave turns it into an S), with the ribbon's width always across the curve. `StrokeLayer` draws each layer twice: the solid paint (opaque, writing depth), then the thin paint blended over what's behind. Plants are sorted back to front from the day camera, curve and wave a little, and melt into the ground at the root. Big surfaces (sky, ground, mountains) place strokes in the fragment shader (`painterly/strokeField.ts`): a grid of strokes along a flow direction, each painted in the one color found at its centre, so gradients turn into blocks of paint; the two topmost strokes glaze over each other. Every stroke is anchored to the world and moves only with the wind.
- **Cursor wind (day).** The cursor is the origin of a strong wind. `CursorWind` writes `gustUniforms` (`painterly/gust.ts`): the cursor's screen position and a strength that rises hard while the cursor moves and eases off after. Plants and pollen measure the wind on screen (`cursorGust`), so whatever is drawn around the cursor bends away from it, in gusts that run outward in rings. It is off on touch screens, with reduced motion and while a project overlay is open, and dies down as the camera leaves for the top view. `cursorWind` in the look sets its strength.
- **The layout (day).** The meadow follows the site's flower plan: standing at the edge of the meadow, the camera looks down a little onto groups of flowers, across the field to the forest edge and the mountains. A stream (`streamX` in `painterly/landscape.ts`, painted into the ground by `Terrain`; nothing grows in it) comes out of the forest edge and winds off to the left, a stand of tall firs frames the right, and a lower forest edge runs across the back (`scatterConifers`). Every section of the site is a bed of one flower (`PROJECT_BEDS` in `src/config/flowers.ts`): Vita & About is baby's breath (Schleierkraut), the three portfolios are poppies (Mohn), ox-eye daisies (Margeriten) and rampion bellflowers (Rapunzel-Glockenblume), the shop is cosmos (Cosmea) in pink, white and deep rose. Imprint and contact live in the footer, so their flowers, marsh marigolds with buttercups by the stream and pot marigolds (Ringelblumen), grow without a link (`MEADOW_BEDS`), together with drifts of the wild flowers between the beds: meadow sage, red clover, ribwort plantain and round-headed rampion (Teufelskralle). Each species has its own painter in `painterly/plants.ts` (`FLOWER_SPECIES`). `scatterBeds` (`painterly/beds.ts`) places the plants of every bed, shared by the painted beds (`FlowerBeds`) and their dust twins. `Flowers` scatters the same species sparsely around the beds and out to the horizon.
- **Flower beds as the menu (day).** The project beds react as groups, never single flowers. `FlowerBeds` paints all beds into one stroke layer whose strokes carry their project bed's index (`Stroke.feature`). The project beds breathe a soft HDR glow (`featuredGlow` in the palette, so bloom picks it up), and now and then, at random (`BED_PULSE`), a pulse of light ripples through one of them, plant by plant, as a hint that it can be clicked. Strengths are `featured*` in the look. Since the canvas ignores pointer events, `FlowerBeds` casts the cursor ray against each bed's areas at a few heights (`BED_HIT`); the nearest bed along the ray goes to the store as `hoveredBed`, and the cursor dot grows. `FlowerHoverLabel` (DOM) reads it and shows the bed's `title` and `teaser` (teasers are placeholders for now) in a small frosted label next to the cursor. Under the cursor the whole bed lights up in its own colors, grows a little and stands still in the cursor's wind (`featuredUniforms` in `painterly/featured.ts`). On narrow screens the beds move in with the trees (`uTreeSqueeze`), and so do their hit areas and the room the wild flowers leave for them (`bedGapGLSL`). Hover only works by day and with a mouse; the glow fades out with the morph into the night. A click, or a tap on touch screens, is hit-tested the same way at its own position (`FlowerBeds` listens on the window and ignores clicks on buttons, links and dialogs) and sets `openBed`. `ProjectOverlay` (DOM) shows that section in a modal `<dialog>`: a panel sliding in from the right over two thirds of the screen on desktop, a sheet sliding up over nearly the whole screen on mobile. The panel is opaque and pushes the stage aside: `SceneCanvas` slides the canvas wrapper by half the panel (left on desktop, up on mobile) in step with it, both timed by `--overlay-duration` and `ease-overlay` in `globals.css`, and the site's chrome fades out (top navigation, wordmark, sound toggle and footer, `useOverlayFade`; it fades out with the night panel too). It closes with its button, Escape or a click beside it, and slides out before the dialog closes. While it is open, `useSectionScroll` stops Lenis (the panel scrolls natively via `data-lenis-prevent`; if the page has a scrollbar, a stable gutter keeps the viewport from resizing when Lenis clips the page), hovering and the cursor wind pause, and the open bed stays lit.
- **Wet in wet.** So the day reads as one painting rather than objects side by side, strokes mix into the paint around them. `WetCanvasPass` (first in the effect chain) keeps a blurred copy of each frame; on the next frame every stroke and the ground pick up its color at their position (`wetMix`), most where their own paint is thin or runs dry. They take on the neighbouring hue but mostly keep their own lightness, so edges between colors melt without the picture going muddy. `wetBlend` in the look sets the strength; it fades out as the day morphs into the night.
- **Post-processing.** After the wet canvas capture (see above), `VolumetricMist` raymarches soft banks of mist against the scene depth (so they wrap around plants instead of clipping), lit by the low sun and thinning out as the day morphs into the night. Then depth of field focuses on the near meadow, a little below the centre of the frame (a ray march against `terrainHeight` every frame), so the field melts into soft paint behind. The sky only blurs a little, so the sun stays a whole disc. It hands over to the dust's own bokeh as the painting turns into dust. Then bloom on the HDR highlights (the sun, backlit petal edges, pollen), then the finish in its own pass (`PainterlyEffect`: chromatic fringe toward the edges, canvas texture by day, grain, a vignette that closes in at night).
- **Depth layers (day).** Background: `Sky` (gradient, painted clouds, a low sun and the moon), `Stars`, `Mountains` (layered ridges fading into haze) and `Conifers` (the forest edge, with the stream coming out of it). Midground and foreground: `Grass`, the `FlowerBeds` and the wild `Flowers` on the `Terrain`, the tall firs on the right. Over it all, volumetric mist low along the trees and at the bottom corners of the frame, and `Pollen`, glowing where the low sun shines through it.
- **Look settings and quality tiers.** `src/config/look.ts` holds the tunable defaults (focus range, blur, grain, vignette, density, wind, cursor wind, glow) and two quality presets. `src/store/look.ts` is the runtime copy, canvas-internal. The tier is detected once (`src/lib/quality.ts`). Phones and weak machines get "low": fewer instances, a lower dpr and a smaller DoF buffer. Use `?quality=low|high` to force a tier.
- **Ambient sound.** `src/lib/ambient.ts` synthesizes the sound with Web Audio; there are no sound files. By day an airy wind (band-passed pink noise in slow gusts, a breath of high air, a faint whistle), by night a darker room (a low rumble, a breathing drone on an A minor chord, a shimmer of dust). The two cross-fade with `night`, and the flight between them rushes. Cursor speed stirs the world under it: it blows up the day wind and makes it brighter (panned toward the cursor), and at night it raises the dust shimmer and opens the drone. Under both runs a calm piano loop in A minor (eight bars, a broken chord and a sparse melody, synthesized from a few partials per note) whose notes stay the same through the switch; by night it turns slightly electric (a Rhodes-like FM bark and tine, a gentle tremolo) and wetter. Every click (also on the nav and from the keyboard) plays a soft click tuned into the world: a pitched tick in A minor pentatonic (the note picked by cursor x), bright and short by day, low and ringing by night, through the same reverb, and it stirs the ambience for a moment. The entry screen's choice turns it on or off (`setSoundEnabled`, which creates the engine; the on/off state lives in `src/store/sound.ts`), and `SoundToggle` (top right, lucide icons) switches it afterwards. The master level swells in with the intro build-up (`intro` squared, smoothed by `swell`). Should the browser still hold audio back, the engine stays on and starts with the next click, key or tap. It fades out while the scene is `"hidden"` and suspends while the tab is in the background. Levels and frequencies live in `src/config/sound.ts`.
- **The night map is the consulting site.** By night the world is Simone's consulting landing page (after the briefing "Landingpage rsgnl consulting"), seen from the top view as a dark map: the woods with seven clearings on the left (the challenges, in three areas plus one at the forest edge, each a grove of trees that glows and pulses as a group, like the day's flower beds), the city with six lights on the right (the services, four big, two small) joined by roads, the mountains along the top with the summit (the result), the goal at the top right (contact, the brightest light), the meadow at the bottom (about), a lantern on subsidised paths (BAFA, `BAFA_ENABLED`) and testimonials as fireflies. `src/config/nightMap.ts` is the single source of the layout (places, roads, paths, the map frame), `src/content/consulting.ts` holds all copy (German, keyed by the same ids). The woods are a share of the shared conifer layout (`scatterConifers`, appended with their own random sequence and thin inside the day view, so the day doesn't change), and so are the groves in the clearings (`scatterGroves`, appended last, night only: `Conifers` doesn't paint them, so by day the clearings stay open); their dust trees carry their clearing's place and glow with its hover and path state (`Dust`, reading `mapUniforms`). The city's buildings are night-only dust in the trees' style: `painterly/city.ts` lays out squat boxes in the blocks of the street grid (leaving the lights, roads and paths free), and `Dust` scatters specks over their walls and roofs; everything else on the map is night-only light: `NightMap` (in `DustWorld`) draws `MapLines` (every trail, road and street as dots in one draw call; a hovered or opened path draws itself in from its clearing and retracts the same way) and `MapLights` (the glow of every place but the clearings, one instanced draw call), shared geometry lives in `painterly/nightMap.ts`.
- **Two patterns on the map.** A click on a clearing lights its path (it stays lit) and opens the panel, which tells the path as one story: the challenge, the first service, the road (why both belong together), the second service, the result, the goal. As the panel scrolls through these steps (`data-step`), `NightPanel` writes `pathStation`; the camera (`CameraRig`) and the light (`Nightingale`) follow along the path, and the path lights up as far as it has been read. Every other place is a light: hover or focus shows a one-to-two-line preview, a click opens the panel. The places are real buttons (`MapPlaces`): the canvas projects them to the screen every frame into `placeScreen` and a frame loop moves the buttons there, so the map works with the keyboard and screen readers. On touch screens the first tap lights the place and shows its preview in a card fixed at the bottom centre ("Antippen zum Öffnen"); a second tap on the place or the card opens it, a tap anywhere else lets it go.
- **The night panel.** `NightPanel` (half the screen on the right, dark, on mobile a sheet over two thirds of the screen, so the map stays in view above it) shares its dialog shell with the day overlay (`SlidePanel`). The canvas slides aside by a quarter (on mobile up by a third), and the camera frames the panel's focus (`panelFocus`: the open place, or the point on the path) in the half left free (on mobile the strip above the sheet); overviews (services, process, questions) show the middle of the map (on mobile all of it, in the strip). Every panel ends with "Termin vereinbaren" and one or two related panels; the map moves with them. The navigation (services, process, about, the glowing "Erstgespräch vereinbaren") and the night footer (questions, contact, imprint) open it too.
- **The night intro.** The day -> night flight is the intro: the first time the night is chosen, `NightIntro` shows the visitor's situation line by line as the camera comes in to land (skippable, all at once with reduced motion), then asks them to pick a clearing. The map takes clicks once it is done (`nightIntro`). On portrait screens the map is turned a quarter (woods at the top, city below, mountains on the right), so it fills the screen.
- **The navigation morphs.** The Day/Night switch reads "Kunst" and "Consulting". By day it stands alone in the pill; by night the consulting site's items follow it (`NavItems`), and on a switch the old set fades out, the pill eases to the new set's width, the new set fades in.
- **The same frame on every page.** The root layout mounts the wordmark "rsgnl" at the top left (`SiteBrand`, it never changes and sits out the page slide) and the footer (`SiteFooter`): by day and on sub-pages imprint and contact, on the night map questions, contact and imprint. Over the scene both are fixed and their colors cross over with it; on a sub-page they sit at the top and the end of the page.
- **All copy is German** (`<html lang="de">`).
- **Pages control the scene through `sceneMode`.** A page claims the canvas with `useSceneMode("home")`. On unmount it falls back to `"hidden"`, which stops the frameloop and hides the canvas. A new route that doesn't call `useSceneMode` therefore gets a paused, invisible canvas. To add a mode, extend `SCENE_MODES` and `sectionsByMode` in `src/config/scene.ts`.

## Folder structure

```
src/
  app/                 Routes (home, imprint), root layout (mounts the canvas), global CSS and design tokens
  components/
    canvas/            Canvas setup: SceneCanvas, the client-only loader, frameloop control
      scene/           Scene parts: CameraRig, Sky, Lights, PaintedWorld (Terrain + Mountains,
                       Vegetation: CursorWind, Conifers, Grass, FlowerBeds, Flowers, Pollen), StrokeLayer,
                       Nightingale, DustWorld (Dust, Fireflies, CursorLight), Stars, Effects
      painterly/       Shared toolkit: palette, light and view uniforms, GLSL chunks, the
                       night light and morph, dust uniforms and trail, the nightingale's strokes and material, the cursor gust, the flower beds' layout and glow, the brush simulation, strokes and
                       stroke fields, plant painters, landscape shape and conifer layout,
                       PainterlyEffect, WetCanvasPass, VolumetricMist, RNG
    cursor/            The dot cursor (CursorDot), mounted in the root layout
    nav/               Top navigation (TopNav: one pill with the Day/Night switch and the night's items; below md the burger menu, MobileMenu), the wordmark (SiteBrand) and the footer (SiteFooter) mounted in the root layout, and the sound toggle
    ui/                Shared UI primitives: Button (and ButtonLink), the one button of the site, with its variants and sizes
    night/             The night map's DOM: the place buttons (MapPlaces), the side panel and its content (NightPanel, PathStory, PanelContent, PanelParts) and the intro
    sections/          DOM sections, the entry screen, the flower hover label, the day's hint (DayHint), the project overlay, the shared slide panel (SlidePanel) and per-page scroll controllers (e.g. HomeScroll)
  fonts/               DM Sans (next/font/google) and Calendas Plus (woff2, next/font/local)
  config/              Section config (camera keyframes), scene modes and the night camera, palette, look and quality presets, sound levels, the flower beds, the night map's layout, site name and links (contact email, imprint)
  content/             Copy (German): the consulting site's, keyed by the night map's ids (consulting.ts), and the day's (studio.ts)
  hooks/               useSectionScroll, useSceneMode, usePrefersReducedMotion, useWindowPointer,
                       useIntroRevealed, useReveal
  lib/                 GSAP setup (plugin registration), the Lenis + GSAP ticker integration, quality tier detection, the ambient sound engine
  store/               The zustand store bridging DOM and canvas, the canvas-internal look store, and the sound on/off store
```
